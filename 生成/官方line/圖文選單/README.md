## 怎麼產生的

**先排出完整的 2500 × 1686 一整張，再切成五塊。**

這點很重要：如果五張各自畫，底色紋理、分線位置、照片邊緣都會對不齊，
拼起來一眼就看得出是六塊拼湊的。從同一張切，接縫一定準。

`產生圖片.js` 會自動做完整流程：排版 → 截圖整張 → 切成五塊 →
另存一份 `_組合預覽_2500x1686.png`（只是給人看的，**不要上傳**）。

### 四角花飾的來源

四角用的是使用者提供的參考圖（`raw/品牌識別/參考-古典花草框.jpg`，640×909）
裁下來的花飾，不是程式畫的。做法：

1. 四角各裁一塊（約 225×250）
2. **以亮度轉成透明度**取出花飾：`-colorspace gray -negate -level 33%,76%`
   —— 深色線條留下、淺色紙面變透明
3. 放大 190%，轉 base64 存進 `素材/corner_*.b64`，內嵌進頁面

去背而不是整塊貼，是因為來源是直式 A4、底色與我們的色帶對不上，
整塊貼會留下明顯接縫。

色帶 `#CBA67D` 與紙面 `#FCF8EC` 都是從參考圖直接取樣的。

> **版權**：此素材由使用者提供並確認可用。來源疑似為付費素材站，
> 若日後要更換，可改用程式繪製版本（見 git 歷史的 `SPRAY()` 函式）。

### 鮮花優雅的做法

內部花飾的配色**配合四角的褐色素描調整過** —— 灰玫瑰 `#AD848A`
配橄欖綠 `#A09A7C`。原本用的粉紅＋薄荷綠太鮮，跟褐色素描框是兩套語言，
放在一起會打架。

| 元素 | 做法 |
| :--- | :--- |
| 外框 | 62px 米黃色帶，內緣一道淺褐細線 |
| 四角 | 參考圖去背的素描花飾（非程式繪製） |
| 分線 | **黑色細藤蔓** —— 波浪主莖交錯長出尖葉與串珠 |
| 分線中央 ／ 標題上方 | **黑色剪影花藤**：漸細捲鬚＋尖葉＋串珠，左右對稱 |
| 照片 | 淡化降到 74%、飽和度 72%，讓蛋糕的顏色透出來 |

### 黑色剪影花藤怎麼畫的

這個風格的關鍵是**捲鬚要由粗漸細**，像毛筆收尾。SVG 沒有變寬度的線條，
所以把一條捲鬚拆成四段路徑，線寬 12 → 8 → 5 → 3 依序遞減，
接起來就有漸細的效果（`CURL()`）。

尖葉是填色路徑的不對稱槍頭形（`LF()`），末端綴由大到小的串珠（`BEADS()`）。
只畫左半，右半用 `scale(-1,1)` 鏡射，確保完全對稱。

分線藤蔓是**重複貼圖**，橫向直向各畫一次，不用 CSS 旋轉。
中央的花藤直向版則是在 SVG 內部繞中心旋轉並交換 viewBox 與寬高。

> 畫到一半發現花藤太細瘦像觸鬚 —— 主莖從 9 加粗到 12、葉片從 46 放大到 58
> 才有份量。另外直向花藤原本 330px 寬，會撞到「聯絡我們」的字，縮到 250px。

### 為什麼不走金色巴洛克

試過兩版：三層金框加捲葉紋，以及滿版捲草鏈加大型花冠。
在 2500px 設計稿上都很華麗，但**縮到手機的 390px 就垮了** ——
金色在米白上對比太低，細密的捲草糊成一團雜訊。

關鍵是：**小尺寸下顏色讀得出來，細節讀不出來。**
粉與綠在奶油白上一眼就是花，金在米白上只是一團淺色。

### 讓它看起來是一整塊

| 做法 | 原因 |
| :--- | :--- |
| 沒有每格各自的外框 | 有框就會變成六張卡片 |
| 全版共用一層淡紙紋 | 同一塊材質，而不是六塊拼起來 |
| 分線只畫在真正的格線上 | 上排只有一條（因為前兩格是合併的） |
| 分線兩端內縮 62px | 不碰到邊緣，看起來是切分而不是框線 |
| 「雪花酥」照片右緣做漸層 | 不然硬邊會被誤認成分線，以為上排有三格 |

分線寬 9px、深灰褐 `#5A5049`。看起來很粗，但縮到手機上只剩約 1.4px，
再細就看不見了。

### 捲葉紋

照 logo 的**語彙**做的，不是照抄。把 logo 放大看，兩側是巴洛克捲葉紋 ——
捲曲的渦卷配飽滿尖葉、左右對稱、實心填色。

同一套語彙做成繁簡兩版，依位置長短挑：

| 版本 | 用在 | 組成 |
| :--- | :--- | :--- |
| 繁版 | 橫向長分線（2376px） | 中央棕櫚葉＋上下尖葉＋外側渦卷＋端點圓珠 |
| 簡版 | 直向分線、格內飾紋 | 中央棕櫚葉＋上下尖葉＋端點圓珠 |

分線結構是「線—紋飾—線」：兩段線用 flex 撐開、紋飾固定寬度，
所以不管分線多長，紋飾都不會被拉變形。

**直向紋飾不是把橫的用 CSS 轉 90 度。** 那樣元素的佔位框不會跟著轉，
渦卷會跑出線外變成飄在旁邊的鉤子。正確做法是在 SVG 內部旋轉內容、
同時交換 viewBox 與寬高，讓佔位框也是直的。

產生圖片時會檢查每個紋飾有沒有超出所屬分線的框，有的話在終端機警告。

## 設計

配色直接取自品牌既有素材，不是另外挑的：

| 色 | 取自 |
| :--- | :--- |
| 深灰褐 `#4E463F` | logo 的剪影與字 |
| 分線 `#5A5049` | 同上，略深 |
| 淡玫瑰 `#A8646D` | 菜單海報的外框（加深以利辨識） |
| 金 `#BFA571` | 菜單海報的麥穗 |
| 米白 `#FCF9F5` | 海報底色 |

字體 **LXGW WenKai TC（霞鶩文楷）** —— 楷書手寫風，呼應菜單海報上的毛筆字。

### 為什麼是這一套

Google Fonts 上的中文手寫字體大多**只有簡體**，繁體缺字會無聲地跳回預設字體，
同一行字出現兩種樣式才發現。實際渲染比對過（見 `_字體比對.png`）：

| 字體 | 結果 |
| :--- | :--- |
| Ma Shan Zheng、Zhi Mang Xing、Long Cang、Liu Jian Mao Cao | ❌ 「節慶禮盒」「聯絡我們」等整組跳字體 |
| Yuji Syuku（日系毛筆） | ❌ 「**糕**」缺字 —— 蛋糕、鮮奶油蛋糕都會壞 |
| Klee One（日系硬筆） | ❌ 「**奶**」缺字 |
| **LXGW WenKai TC** | ✅ 價目表全部品項 74 字完整一致 |

拿價目表上**所有**品項去測，不是只測選單上這六個詞 ——
每週特賞每週換品名，哪天換到缺字的品項才發現就來不及了。

字重 700（該字體最粗）。楷書筆畫本來就比明體細，所以標題比明體版再放大一級補回視覺重量。

有照片的三格，照片都壓了一層 78% 米白並降飽和度到 50%，
讓字清楚但照片仍看得出內容。

### 字級

圖文選單在手機上只有約 390px 寬，每格縮到約 130px，所以字要比直覺大很多。
五格的標題**一律 160px**，不因字數少就放大 ——
兩個字的「蛋糕」放大到跟四個字同寬，看起來會比旁邊重，像是被特別強調。
同字級排在一起才整齊。

160px 是四個字能排得下的上限（含 0.14em 字距）。

「雪花酥」是本週主打、位在合併的大格裡，維持 196px。

字重用 700 而非最粗的 900，字距拉到 0.14em —— 太粗太擠會變得現代而笨重，
古典襯線要留得出呼吸的空間。

「本週特賞」84px，規格 74px，**價格 132px**。
價格刻意不做大：數字一大就壓過整個版面，變成特價傳單而不是品牌選單。

產生時會檢查文字與紋飾有沒有超出框，有的話會在終端機警告。

## 每週要換的那張

本週特賞每週換一次。傳新照片過來，告訴我品名、容量與價格即可。

也可以自己改 `產生圖片.js` 最下面的 `JOBS`：

```js
{f:'1-1_1-2_本週特賞_雪花酥.png', w:1686, h:843,
 html:weekly('雪花酥', b64('snow'), '850g／包', '200元')},
```

`weekly(品名, 照片, 規格, 價格)`。照片要先縮成 1100×1100 的 jpg、
轉 base64 存成 `<名稱>.b64` 放在同一層，再執行 `node 產生圖片.js`。

> 品名以這裡寫的為準。注意菜單海報上印的是「雪花**餅**」，
> 而這張用的是「雪花**酥**」—— 兩者要統一，見 規則/產品價目表.md 第六節。
