# 訂單管理 App

雙人共用的 PWA 訂單管理介面。這是目前**唯一已實際運作**的系統。

> 依據：《[營運與開發整合紀錄](../../規則/營運與開發整合紀錄.md)》第 07 節
> 技術分析：《[訂單資料分析](../../規則/訂單資料分析.md)》

## 架構

```
        手機／電腦 PWA 網頁介面
                 ⇅
Google Apps Script 網頁應用程式（API）
                 ⇅
     Google Sheets：Orders 工作表
```

## 本資料夾的檔案

| 檔案 | 用途 |
| :--- | :--- |
| `index.html` | 完整 App：登入、訂單清單、多品項訂單、刪除、狀態篩選、收支紀錄（單一檔案） |
| `Code-後端擴充.gs` | **單一一份**後端擴充：收支紀錄、多品項明細、刪除訂單、日期根治。需手動併入 Code.gs 並重新部署 |
| `備份/` | 改動前的原始版本 |
| `manifest.webmanifest` | PWA 設定：名稱、圖示、加入主畫面 |
| `icon-180.png` | Apple touch icon |
| `icon-192.png` / `icon-512.png` | PWA 圖示 |

所有路徑皆為相對路徑，整個資料夾可搬到任何位置而不影響運作。

## ⚠️ 不在此資料夾的關鍵檔案

**`Code.gs`（Apps Script 後端）尚未納入版本控制。**
目前只存在於線上的 Apps Script 編輯器中，遺失即無法還原。
整合紀錄第 10 節已將「資料遺失或誤改」列為**高風險**。

建議盡快把該檔案貼進此資料夾一併版控。

## 畫面結構

```
開啟 app
   ↓
登入畫面（Apps Script 網址 + 共用密鑰）   ← 每次開啟都會先看到
   ↓ 登入成功
訂單清單                                 ← 預設畫面
   ☰ 選單 ─ 訂單清單
          ─ 收支紀錄
          ─ 登出
```

**登入**

- 網址記在手機的 `localStorage`，下次自動帶入；**密鑰一律不保存**，每次重開都要輸入
- 按「登入」會**實際呼叫一次後端驗證**，密鑰錯誤會留在登入畫面並顯示原因
- 登入前 ☰ 選單不會出現，登入後連線設定就不再出現在任何畫面
- 「登出」清掉記憶體中的訂單、收支與密鑰，回到登入畫面（網址保留）

## 訂單狀態、收款與歷史訂單

訂單有**兩條獨立的軸**，兩條都走完才算結案：

- **製作進度**（訂單狀態）—— 卡片上的快捷按鈕一步一步推
- **收款**（付款狀態）—— 不在製作流程裡，另外處理

### 製作進度

| 目前狀態 | 卡片上的按鈕 | 按下後變成 |
| :--- | :--- | :--- |
| 待確認 | 確認訂單 | 已成立 |
| 已成立 | 開始製作 | 製作中 |
| 製作中 | 完成製作 | 待交付 |
| 待交付 | 已交付 | 已完成 |
| 待付款 | 確認成立 | 已成立 |

`待付款` 不在主流程上，只有手動設定時才會出現，留一顆按鈕讓它不會卡住。

### 收款

收款**不是製作流程的一步**，所以「已收款」不會出現在流程按鈕的位置，
而是放在橘色提醒條裡，與製作流程分開：

```
⚠️ 已交付，尚未收款 NT$ 1,000      [已收款]
───────────────────────────────────────
[ 查看／修改 ]                      [ 🗑 ]
```

訂單走到 `已完成`（已交付）而款項還沒收齊時才出現：

| 付款狀態 | 卡片上的提醒 |
| :--- | :--- |
| 未付款 | ⚠️ 已交付，尚未收款 NT$ 1,000 |
| 部分付款 | ⚠️ 已交付，款項尚未收齊 NT$ 750 |

**交付前不會提醒** —— 還沒出貨就催款沒有意義。
已付款與已退款也不會提醒。

按「已收款」把付款狀態設為已付款。要記訂金或部分收款，
走「查看／修改」選「部分付款」。

### 歷史訂單

從 ☰ 選單進入。一筆訂單符合以下任一條件就會從訂單清單移到這裡：

- 訂單狀態 `已完成` **且** 付款狀態 `已付款`（或 `已退款`）
- 訂單狀態 `已取消`

只做完沒收錢、或只收錢沒做完，都**還留在訂單清單**，因為還有事要辦。
結案的當下，同步列會提示「這筆訂單已結案，移入『歷史訂單』」。

訂單清單的摘要列會顯示歷史訂單的筆數，歷史訂單依最後更新時間新到舊排列。

## 刪除訂單

每張訂單卡片的按鈕列最右邊有一個小垃圾桶（🗑），與「查看／修改」「完成製作」同一列。

- 會先跳確認視窗，列出顧客、商品與金額，按取消**不會送出任何請求**
- 刪除會帶上該筆的 `updatedAt`；若另一支手機剛改過，後端會拒絕並要求先重新整理，
  避免蓋掉對方的修改
- 刪除是真的刪掉試算表的那一列，**無法復原**。只想保留紀錄的話，改用訂單狀態「已取消」

### ⚠️ 需要先更新後端

`delete` 這個 action 現有 Apps Script 還沒有。未更新前按下垃圾桶會跳出
「刪除失敗：未知的 action：delete」並說明要先更新後端，**不會刪掉任何東西**。

## 多品項訂單

一張訂單可以有多個商品。每個商品是一個區塊：**商品名稱、數量、單價**。
按「＋ 新增商品」加一個區塊，兩個以上時每塊右上角有「刪除」。

兩層自動計算，都不能手動改：

- 每個區塊的**小計 = 單價 × 數量**
- 下方的**總金額 = 所有小計相加**

輸入單價或改數量時兩者即時連動。

### 資料怎麼存

訂單多了一個 `items` 欄位（陣列），同時 `product`、`quantity`、`amount`
改為**自動產生的摘要與合計**：

| 欄位 | 內容 | 範例 |
| :--- | :--- | :--- |
| `items` | 完整明細（JSON 陣列） | `[{product:"雪花餅",quantity:6,price:200,amount:1200},…]` |
| `product` | 品名摘要 | `雪花餅、蛋黃酥6入` |
| `quantity` | 數量合計 | `7` |
| `amount` | 金額合計 | `1680` |

每一項的 `amount` 是該項小計（`price × quantity`），訂單的 `amount` 是所有小計相加。

這樣即使 `items` 沒存成功，試算表上仍看得懂、合計仍正確。

`product` **只放品名、不帶數量**。帶了數量的話，在 `items` 沒存成功的情況下，
下次載入會把整串摘要當成品名，存檔時再接一次數量，每編輯一次就多疊一層
（`雪花餅 ×5` → `雪花餅 ×5 ×5` → …）。只放品名則是可重複套用的，存幾次都一樣。

### ⚠️ 需要先更新後端

`items` 需要 Orders 工作表多一欄，見 `Code-後端擴充.gs`。

**未更新前 App 仍可正常使用**：多品項照常輸入與加總，摘要與合計也會正確存下，
只是「拆成幾項、各多少錢」的明細不保留，下次編輯會併成一個區塊。
App 會在儲存後**自行偵測並在同步列說明**，不會默默吃掉資料。

舊訂單（沒有 `items`）開啟編輯時會自動帶成單一商品區塊，不需轉檔。
舊資料的 `amount` 原本是該筆的總額，會**除以數量推回單價**（例：200 ÷ 5 → 單價 40）。
現有 4 筆測試資料都能整除，推回後總額不變。

## 收支紀錄

從 ☰ 選單進入。

| 區塊 | 內容 |
| :--- | :--- |
| 月份摘要 | 已收營收、支出、毛利三欄，另列支出分類小計 |
| 新增支出 | 日期、分類（材料／包材／設備／運費／其他）、項目、金額、備註 |
| 本月支出明細 | 可點進去修改 |
| 本月待收款 | 該月未付款的訂單，方便對帳催款 |

**計算規則**

- 營收**只計「已付款」訂單**。「部分付款」實收金額不明，不猜測，另以提示列出。
- 歸月依**交付日期**；未填交付日期者改以最後更新日期歸月。
- 已取消的訂單一律排除。

這些規則直接寫在畫面上，不需要翻文件。

### ⚠️ 需要先更新後端

支出要存進試算表的 `Expenses` 工作表，而**現有 Apps Script 還不認得**
`listExpenses` 與 `saveExpense` 兩個 action。

在併入 `Code-後端擴充.gs` 並重新部署前：

- 收支紀錄畫面**仍可使用**，會正常顯示訂單營收與待收款
- 支出清單為空，並顯示「後端尚未支援收支紀錄」
- 按「儲存支出」會跳出提示並**不送出任何資料**（不會寫壞東西）

`Code-後端擴充.gs` 裡有完整的合併步驟與 `doPost` 範例。
由於原本的 `Code.gs` 不在儲存庫裡，該片段是依前端契約寫的，合併時請對照你的實際寫法。

## 版本與自動更新

GitHub Pages 對 HTML 設 `Cache-Control: max-age=600`，所以改完程式後，
手機上最多會有 **10 分鐘**還是看到舊版。這曾經造成「明明改了卻看不到」的誤判。

處理方式：

- `version.txt` 放當前版本戳記（`YYYYMMDD-HHMM`），`index.html` 裡有相同的 `APP_VERSION`
- 開啟 App 時以 `cache: 'no-store'` 讀 `version.txt`（小檔案，不受 HTML 快取影響）
- 版本不一致就帶 `?v=<新版本>` 重載一次 —— 查詢字串是不同的快取鍵，會拿到新檔
- 已經帶過該版本還是不一致（伺服器仍回舊檔），就**只提示不再重載**，避免無限循環
- 頁尾永遠顯示目前版本，要確認對方手機上跑的是哪一版，看那一行就好

根目錄的轉址頁也會附加時間戳。

**發新版時務必同步更新兩處**：`index.html` 的 `APP_VERSION` 與 `version.txt`。

## 使用方式

1. 開啟 app → 出現登入畫面
2. 第一次：貼上 Apps Script 的 `/exec` 網址（之後自動帶入）
3. 輸入共用密鑰
4. 按「登入」→ 直接進入訂單清單
5. 要看收支、或要登出，點左上角 ☰

另一支手機修改後，需按「重新整理」才會看到。

## 已修正的缺陷

**交付日期會被靜默清空**（commit `9c70943`）。
試算表會把 `due` 自動轉成日期型別，讀回時變成 ISO 時間字串
（且因時區差而早一天），`<input type="date">` 無法接受，
導致編輯訂單後日期被寫成空值。
已於前端加入 `normDate()` 正規化，並經無頭瀏覽器於 `Asia/Taipei` 驗證。

根治仍需後端配合，詳見訂單資料分析第 3.5 節。
